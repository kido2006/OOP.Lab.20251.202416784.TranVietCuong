2. When overriding the equals() method of the Object class, you will have to cast the Object parameter obj to the type of Object that you are dealing with. For example, in the Media class, you must cast the Object obj to a Media, and then check the equality of the two objects’ attributes as the above requirements (i.e. title for Media; title and length for Track). If the passing object is not an instance of Media, what happens?

The equals() method must return false.  
If the object is not an instance of the expected class, it cannot be compared meaningfully, so the method should not perform a cast and must return false to avoid errors.


3. What class should implement the Comparable interface?

The Media class should implement Comparable<Media>, because Media is the parent type stored in the cart and used for sorting.


4. In those classes, how should you implement the compareTo()method be to reflect the ordering that we want?

To follow the default ordering rule, compareTo() should compare titles alphabetically (ascending). If titles are equal, compare costs in decreasing order.  

5. Can we have two ordering rules of the item (by title then cost and by cost then title) if we use this Comparable interface approach?

No.  
Comparable allows only one compareTo() method, so only one sorting rule can be implemented. Multiple ordering rules require using separate Comparator classes instead.


6. Suppose the DVDs has a different ordering rule from the other media types, that is by title, then decreasing length, then cost. How would you modify your code to allow this?

I will create a new Comparator specifically for DigitalVideoDisc.

This custom comparator will:
1) Compare titles alphabetically.  
2) If equal, compare DVD lengths in decreasing order.  
3) If still equal, compare costs.
